# 标签锚定的竞争类别验证：详细实验计划

版本 v1，2026-10-20，北京时间。此计划先于新竞争分数的真实结果固定。机器参数以同目录上级的 `protocol.json` 为准；任何修改先提交新版本并说明原因，不能覆盖旧结果后改口径。

## 1. 研究问题与第一版范围

研究问题是：分类器认为有竞争力的类别，是否也得到真实标注原型的支持；这种类别对应关系能否在分类器与原型冲突时，区分分类器的真实错误和原型误报，并改善伪标签权重？

第一版只使用已有模型的概率、已有 decoder 特征、每类一个标注原型，以及一个小型正确性评分器。不增加编码器、时间记忆、图优化、多原型或新伪标签类别。原伪标签保持为分类器的 argmax。此前静态 RCV 的负向／混合证据继续保留，不转写为新方法证据。

对像素 i，令 a=argmax z，m=p_a，f 为归一化特征，μ_k 为标注类别原型，s_k=cos(f,μ_k)。定义

\[
r_k=\operatorname{softmax}(z_{-a})_k,\quad
c_k=[s_k-s_a]_+,\quad
e=\sum_{k\ne a}r_kc_k.
\]

代码直接在排除 a 后的 logits 上做 softmax，避免高置信度下 `1-m` 消减或为零。所有分数在 FP32 及以上计算。e>0 的条件与存在严格更强的原型竞争者相同（有限精度另作审计），因此不能仅证明“原型冲突更容易错”；必须评价冲突内部连续排序。e=0 不代表正确，双方一致地错是明确盲区。

权重为 `sigmoid(MLP(logit(m),e))`，MLP 固定为 2→16→1，ReLU，无 BatchNorm/Dropout。目标为当前分类器预测是否等于 GT。评分器只接受 detached 输入。第一版不把它称为已经校准的概率或新统计保证。

## 3. 先固定模型、特征和训练预算

首个正式教师为 seed42，MC≥0.95，主监督只用 D_sup。使用相同获准的预训练 ResNet 权重初始化，不能从见过全部 D_L 的 SSL checkpoint 初始化。训练总步数固定为 **46,240**，即原 80×floor(9259/16)；逻辑 global batch 16，学习率 0.001，decoder LR 倍率 10，沿原多项式曲线。新标注集重复采样到相同迭代预算，避免改变 epoch 长度。

保存三个固定更新点：early=4,624，middle=23,120，late=46,240（10%/50%/100%）。这是新研究的阶段点，不与旧 RCV 的 16/40/72 轮混写。冻结分析不按验证集最优 checkpoint 挑阶段。训练恢复需保存模型、optimizer、LR scheduler、scaler、全局步数、RNG 和 sampler 状态；worker 恢复局限单独记录。

特征固定为 `model.decoder.classifier` 的输入，256 通道，最终 1×1 分类卷积之前，不额外训练投影头。保持原模型 eval 下的 logits 不变，用 hook 采样该特征。按原图像素坐标双线性取特征，`align_corners=True`，取样后 L2 归一化；所有原型和评分方法使用相同对齐。

冻结原型每个 checkpoint 重算一次：只用 D_sup，每图每类最多 2,048 个确定性抽样像素，先计算图内类别的单位特征均值，再对支持该类的图像等权平均，最后归一化。这样避免一个大物体独占原型。保存类别像素数、支持图像数、均值范数、零范数／缺类情况。正式比较缺少任一类原型时停止，不用 D_U/D_rel/validation GT 补缺。

在线训练候选方案是 D_sup 特征的逐类 EMA，β=0.99，仅更新当步出现的类别，所有状态 detached。冻结原型和在线 EMA 是不同估计器，其差异应记录；进入 G3–G7 前必须冻结在线维护、初始化及刷新协议。

## 5. P1：同一冻结模型的四项机制实验

每阶段原型、特征、logits、抽样位置和 GT 均固定。D_rel 上 3-fold GroupKFold 按图像调小评分器，validation 只用于评价。原始分数排序和经过相同小 MLP 的排序都报告，不能只给最有利的输出。

### A. 标签原型提供多少互补信息

输出分类器正确／错误 × 原型分类器正确／错误四格表，其中双方均错再分一致与冲突。报告各格覆盖率、错误数、MC、e 分布、P(e>0|分类器错) 与 P(e>0|分类器对)。分别在总体、MC≥0.95、冲突及高 MC 冲突中评价。

若高置信度错误中可被反证覆盖的比例接近零，先诊断特征和原型，不扩大训练。冲突／分层至少需 20 张含错误图、20 张含正确像素图及各 100 个抽样像素；不足标注为支持量不足，不能把少量像素的高精度作为结论。

### B. 强对照排序

| 对照 | 定义／作用 |
| --- | --- |
| MC、entropy、margin、残余 entropy | 原有纯预测不确定性 |
| s_a | 原型对当前伪标签的普通支持 |
| prototype margin | s_a−max_{k≠a}s_k |
| prototype disagreement | 原型 argmax 是否与 a 不同；单独检查其二值分数的并列 |
| probability–prototype JS | p 与 q=softmax(s/T) 的完整分布 JS |
| product support | (p_a q_a)/(Σ_k p_k q_k)，始终评价原始 a |
| uniform evidence | mean_{k≠a}[s_k−s_a]_+ |
| top-2 evidence | 仅概率第二名对应的 [s_b−s_a]_+ |
| full evidence | Σ r_k[s_k−s_a]_+ |
| native CSL/CoVar | 在相同预测上保留旧方法对照，方向与源码一致 |

融合 T 在 [0.05,0.1,0.2,0.5,1] 中只用 D_rel 图像 CV 选取；由融合对照选定，并在所有方法／条件探针中共享。不是用 validation 给新方法挑有利 T。该融合是“受 HyperMatch 启发的简化对照”，不是完整 HyperMatch 复现。

MLP 无 BN/Dropout，Adam LR=0.003，500 次更新，每次 4,096 像素；L2 候选 1e-4/1e-3/1e-2；以 D_rel 的分组 CV 加权 BCE 选取，然后在全部 D_rel 重拟合。输入均值／标准差仅用训练 fold 拟合，目标为自然正确性比例，不人为平衡正负类。所有版本固定相同初始化 seed2027、更新数和调参预算。MC-only 用 `(logit m,0)`，各两输入对照参数量一致。暂不按 validation 早停。

### C. 类别对应置换

对每个像素仅在计算 e 时打乱 residual 概率与竞争类别的对应关系；保留原始 logits、a、m、相似度以及所有纯预测分数。置换 seeds=0…9，按图像／像素身份确定，不能受 batch 或分块顺序影响。每个置换版本独立按同样协议拟合评分器，避免把输入尺度变化误当作信息损失。

报告原 e、uniform、top-2、十个置换版本的 AP、曲线和区间。比较的是十个版本各自 AP 的平均，不把其预测合并成一个更大 ensemble。只有超过置换还不够，逐类融合也利用类别对应，仍须与 product support 比较。

### D. 条件增量与冲突内部排序

固定 MC 区间、prototype margin 区间，进一步按预测类、阶段、边界／内部像素分组。完整保留支持量不足的行，不删掉难看的类别。控制变量主比较使用

F_base=(logit MC, margin, entropy, residual entropy, s_a, prototype margin, logit product support, probability–prototype JS)，与 F_plus=F_base+e。

两者输入统一补到 9 维，hidden=16，初始化和预算一致；baseline 最后输入为常数零。另报告讨论中的精简 `(m,prototype margin,S_prod)` 与加 e 的对照。主比较不能仅控制 MC 后就宣称超出所有原型信号。

### 统一指标与统计

错误伪标签为正类。AP 使用 average precision，另报 AUROC、错误比例、精确并列处理的连续 AURC、50/70/80/90/95% 覆盖率 precision、90/95/98% precision 对应 coverage、Brier 和 NLL。固定精度同时提供留出 GT 的描述性曲线与 D_rel 选阈值的实际留出精度，明确两者区别。

每图先均匀抽样 4,096 个有效像素，前 1,024 作为主分析，保存逆采样概率权重；同一像素在所有方法和阶段共享身份。4,096 像素作重新拟合的采样敏感性，不能当作独立重复。保留原始位置、logits、特征、GT（评价用）、正确性、全部分数、权重、原型和源码哈希。固定最多 64 张完整图用于可视化与数值检查，选择不依赖效果。

bootstrap 按图像配对 2,000 次，seed2027。主假设族为 late 冲突子集上的四个 ΔAP：F_plus−F_base，h(m,e)−h(m,prototype margin)，h(m,e)−h(m,product)，h(m,e)−置换版本平均 AP。四项使用 Bonferroni 家族 98.75% 区间；其余阶段／子组报告名义 95% 区间，保留全部结果。uniform 是必须报告的机制控制。区间条件于固定模型、原型和已拟合评分器，不包含教师种子与重新拟合总体不确定性。

### P1 继续条件

上述四项 late 主对照区间下界都大于零，至少两个固定阶段的点估计方向为正，总体未出现明确退化，且冲突支持量充分，才进入 seed43 的独立教师确认。uniform 对照若接近完整分数，不能主张残余权重必要。确认阶段先保留同一协议，不重新挑公式。

若只超过 MC、不超过原型间隔或融合，停止以“竞争类别验证”名义扩大完整训练。若结果不确定，记录 inconclusive 和所需证据；不得无限增加模型容量或试到有利分数。signed evidence 只作为已登记的开发备选，选用前必须更新协议，不能用确认集挑选。以上是项目资源门槛，不是会议录用标准。

## 6. P2：端到端核心矩阵

P1 与 seed43 确认通过后，再运行下表。固定 46,240 个 backbone 更新，所有方法保持相同模型、增强、伪标签、无标注损失分支和比例；主结果取固定末步，不用各自最优验证轮数比较。

| 组 | 方法 | 直接监督／评分器监督 |
| --- | --- | --- |
| G0 | 原始 MC≥0.95 | 全 D_L／无 |
| G1 | 原生 CSL | 全 D_L／无 |
| G2 | 原生 CoVar | 全 D_L／无 |
| G3 | h(m) | D_sup／D_rel |
| G4 | h(m,prototype margin) | 同 G3 |
| G5 | h(m,product support) | 同 G3 |
| G6 | h(m,uniform evidence) | 同 G3 |
| G7 | h(m,e) | 同 G3 |

G3–G7 的权重替换 MC 截断，不能再乘 MC≥0.95 后声称恢复低置信度标签。损失按全部有效无标注像素数归一化，weight stopgrad，原始 a 不变。CutMix 时 donor 的伪标签、权重和 ignore mask 必须一起搬运。

在线候选维护方案：前 10% 更新统一使用 MC warmup；之后用 D_sup 建原型，用 D_rel 训练 head，后续每 100 步轮转刷新 4 张 D_rel 图并更新 head 32 次。D_rel 前向在 eval/no_grad，不能更新 BN 或 backbone。原型按 D_sup 当前特征 EMA，仅更新出现的类。此方案须在 P1 后、G3–G7 前通过 smoke 和成本测量锁定，不能在方法间各自调节。

记录每步／阶段的平均权重、加权错误率、ESS、低／高 MC 权重和误标质量。D_U GT 只在独立诊断分支使用，不进入训练决策。增加固定总权重质量的单独控制：`rho_ref * Σ(w*loss)/(Σw+eps)`，rho_ref 从相同 warmup 参考确定，各方法固定，不能逐法看结果调系数。

核心先做 seed42 八组。按 seed42 的固定末步选择旧方法中较强者与原型对照中较强者，后续两种子单独作为确认，不能把筛选种子和确认种子混成无偏选择保证。保留 G0、最强旧方法、G3、最强原型对照、G7 五组，各补 seed43/44，共 8+5×2=18 次完整训练，不含 P1 准备教师和额外质量控制。报告每个 paired seed、均值和标准差；三种子不足以保证微小增益成立。

## 7. P3：直接机制、鲁棒性与完整成本

1. 同覆盖率集合：MC 移除的正确／错误、验证器新增的正确／错误；保存类别、边界和失败可视化。软权重不能用 w>0 定义“选择”，同时报告有效质量和 ESS。
2. 原型来源：同一 D_sup 图像、同一特征，GT 类别归属与模型预测类别归属对照，先离线后决定是否完整训练。
3. 预测过尖锐干预：只增加当前 top-1 logit δ=0/1/2/4。验证 residual 和 e 不变，同时评价最终 h(m,e) 是否被增大的 m 带偏。不得由 e 不变推出最终方法不变。
4. 全局温度 T=0.5/1/2 另作实验，报告实际 NLL/Brier/ECE，不能默认低温必然更失准。
5. 原型支持量：只减少维护原型所用 D_sup 图像至 100/50/25%，主模型监督数据不变；按类别标注频率、独立支持图像数、边界／内部报告结果。分组分析不等于证明解决类别不平衡。
6. batch 重组：冻结 backbone、原型和 head 的 eval 状态，改变样本组 batch 的方式，比较相同像素权重。排除 BN 和在线原型更新混杂。
7. 完整成本：训练 step 时间、峰值显存、GPU 小时，以及原型刷新、D_rel 特征前向和 head 更新成本；微基准另列。删除 SVD 不自动等于整体更快。

## 8. P4：确认范围、算力与进度

完整机制只放在核心 VOC 1/8。之后选择 VOC 更少标注的已有划分、一个已有 DINOv2 设置、Cityscapes 各运行 baseline／最强简单对照／新方法。可以用 Cityscapes+DINOv2 合并确认，但须说明数据集与 backbone 同时改变，不能分开归因。分类只在分割主机制稳定后考虑，不默认沿用极少标签下的 90/10。

排期使用相对时序，不把讨论中的理想日历当成保证：第 0 日完成计划同步、隔离、自检；第 1–3 日在算力／数据齐备后完成正式教师和 A→B→C→D；随后先作 P1 决策再启动 P2。完整训练数量和耗时取决于当前分配 GPU 和真实 step benchmark。用 `剩余步数×实测秒/步` 估算单任务时间，用可同时运行组数估算墙钟时间，计入验证、导出和中断恢复。服务器未连通前不提供虚构 ETA。

若有 6–7 张空闲 3090：优先给一个教师足够的 DDP 资源以维持原 global batch/BN，剩余卡做已完成阶段分析；阶段依赖仍串行，不能在 P1 未通过前并发 18 次正式训练。若只有一张 H100，先基准测量是否能维持 global batch16；不默默改变逻辑 batch、BN 或学习率来凑显存。

## 9. 文档、版本与结果交付

GitHub 新分支为 `research/label-anchored-competition`，不改 main 的研究结论。先提交计划／协议，再提交每次实现和执行记录。公开仓库保存源码、小型配置、汇总 CSV/JSON、测试记录与输入哈希；图像、完整 logits、特征、checkpoint、私钥和环境认证信息不入库。

每个实验分配独立 ID，记录状态（pending/running/complete/failed/blocked/gated）、依赖、命令、Git commit、protocol SHA256、split/checkpoint/prototype 哈希、环境和 GPU、起止时间、退出码、完成标记及结果文件哈希。失败保留，恢复写新事件。仅有日志或 PID 不算完成；只有完成标记与输出校验通过才能改 complete。

首轮交付必须包含四格互补表、完整排序表、冲突内部条件增量表、类别对应置换表和 go/no-go 判断。无论正负均同步；后续训练和泛化按协议门槛推进，不用某张漂亮可视化替代主检验。

## 10. 已核对的主要相关工作边界

[HyperMatch，CVPR 2023，§3.2](https://davar-lab.github.io/files/cvpr2023_hypermatch/HyperMatch-Camera-Ready.pdf) 已使用标注样本 EMA 原型和逐类概率乘积融合，并含 GMM 与 relaxed contrastive loss。本计划的 softmax-temperature product 对照省略这些模块，必须准确标为受启发的简化控制。

[ConMatch，ECCV 2022，Alg.1 与 §3.4](https://www.ecva.net/papers/eccv_2022/papers_ECCV/papers/136900665.pdf) 已使用 feature/logit confidence estimator 和真实正确性监督。因此，小型正确性 head 不是本计划的新颖性本身。需要新增的证据是类别对应的竞争反证是否超过普通原型、融合和学习置信度。当前没有结果支持该主张。
